# Current Internationalization

> Status: Current

The Web package has a small i18n runtime for incremental migration. It is not
yet a complete migration of every user-visible string in the repository.

## Runtime

- The implementation lives in `packages/web/src/lib/i18n.ts`.
- The application mounts `I18nProvider` at the browser entrypoint in
  `packages/web/src/main.tsx`.
- The supported resource locales are `en-US` and `zh-CN`.
- The default locale is `zh-CN`. A previously persisted valid locale takes
  precedence, but the current UI does not expose a locale-switching control.
- Locale resources live in `packages/web/src/lib/locales/`.
- `t(key, vars?)` resolves a resource key and interpolates `{name}`-style
  variables. It does not accept a fallback sentence.
- Missing keys are reported through a console warning and return
  the key so the omission remains visible. Resource key parity is covered by
  `packages/web/src/lib/i18n.test.ts`.

## API error compatibility

`packages/web/src/api/http.ts` understands the target error envelope:

```json
{
  "errorCode": "WORKBOOK_REVISION_CONFLICT",
  "params": { "sheetId": 7 }
}
```

It also reads the current string-based `{ "error": "..." }` envelope while
server endpoints are migrated. The Web client owns the eventual translation of
stable error codes; Server, Core, and Agent must not need to know the user's
display locale.

## Migration boundary

Existing hardcoded UI copy and server-generated sentences remain in untouched
areas. New or modified user-visible copy must follow
[the i18n rule](../rules/i18n.md), and a file should be migrated when it is
touched for another reason. This document must be updated when the runtime
contract changes, not for every individual translation entry.
